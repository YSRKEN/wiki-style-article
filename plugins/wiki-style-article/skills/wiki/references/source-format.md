# 原稿の書き方

原稿は、`+++` で囲んだ TOML の設定欄と、そのあとの本文でできた UTF-8 の 1 ファイル。スクリプトが読み、検査して、HTML とウィキテキストを書き出す。HTML のタグや、本家のテンプレート（Cite web・Infobox など）は原稿に書かない。

## 見本

架空の漫画の記事。

```text
+++
title = "星屑ラーメン"
reading = "ほしくずらーめん"
type = "manga"
defaultsort = "ほしくすらーめん"
categories = ["架空の漫画作品", "グルメ漫画"]
related = ["屋台"]

[infobox]
"ジャンル" = "グルメ漫画"
"作者" = "月見里ほたる"
"出版社" = "架空出版"
"発表期間" = "2020年4月 - 2023年3月"

[refs.official]
kind = "web"
title = "星屑ラーメン 公式サイト"
url = "https://example.com/hoshikuzu"
publisher = "架空出版"
access_date = "2026-11-01"

[refs.vol1]
kind = "book"
title = "星屑ラーメン 第1巻"
author = "月見里ほたる"
publisher = "架空出版"
date = "2020-09-01"
isbn = "978-4-00-000000-0"
pages = "3-20"

[refs.news-start]
kind = "news"
title = "新連載「星屑ラーメン」始まる"
work = "架空新聞"
date = "2020-04-01"

[notes.yomi]
text = "題名の読みは単行本の表記による[^vol1]。"

[[external_links]]
title = "星屑ラーメン 公式サイト"
url = "https://example.com/hoshikuzu"
+++
'''星屑ラーメン'''（ほしくずらーめん）は、[[月見里ほたる]]による日本の[[グルメ漫画]]。架空の月刊誌で2020年4月から2023年3月まで連載された[^news-start][^n:yomi]。

夜の街に現れる屋台のラーメン店を舞台に、店主と客の交流を一話完結で描く[^official]。

## あらすじ

元料理人の店主は、夜の公園の脇で屋台を営む。客は毎話入れ替わり、それぞれの悩みを店主に打ち明ける。最終話で店主は屋台をたたみ、常連客の一人に店を譲る[^vol1]。

## 制作

作者は、屋台を舞台にした理由を、学生時代に通った屋台の記憶だと述べている[^official]。

## 書誌情報

- 月見里ほたる 『星屑ラーメン』 架空出版、全5巻[^vol1]
```

## 設定欄

| 項目 | 必須 | 書くこと |
| --- | --- | --- |
| `title` | 必須 | 記事名。題材の正式名称 |
| `type` | 必須 | 類型の ID。`wiki.sh type` で一覧が出る |
| `reading` | 任意 | 読み仮名（平仮名）。記事名に漢字があれば書く |
| `defaultsort` | 任意 | カテゴリの中で並べるときの読み。本家の慣習に合わせ、濁音・半濁音を清音にする（「ほしくずらーめん」なら「ほしくすらーめん」） |
| `categories` | 任意 | カテゴリ名の配列。分野・種類・年（「2020年の漫画」など）・国のように、探す手がかりになるものを 3〜8 個 |
| `[infobox]` | 類型による | `wiki.sh type <ID>` の雛形を貼って埋める。「必須」の項目は必ず埋め、分からない項目は行ごと消す。値は全部文字列 |
| `[refs.<キー>]` | 任意 | 出典（下記） |
| `[notes.<キー>]` | 任意 | 注釈。`text` に本文を書く。注釈の中にも出典の印を付けられる |
| `related` | 任意 | 関連項目の記事名の配列 |
| `[[external_links]]` | 任意 | 外部リンク。`title` と `url` を書き、繰り返して並べる |
| `[coord]` | 任意 | 位置。`lat`・`lon` を十進で書き（必須）、`type`（`city` など）と `display`（`title`・`inline`・`dms`・`inline,title`。既定は `title`）は任意 |
| `[[navbox]]` | 任意 | 節の下に置くナビゲーションの箱。`title` を書き（必須）、`name`・`state`・`items` は任意。繰り返して並べる |
| `stub` | 任意 | 書きかけの記事のスタブ。値は本家のテンプレート名（`"Japan-geo-stub"` など） |
| `notices` | 任意 | 冒頭に足す警告の枠の配列。`観点`・`出典の明記`・`独自研究` のどれか。ここに書いた枠は `notice_rule` によらず付く |
| `notice_rule` | 任意 | 印から決まる枠の出し方。`多いときだけ`（既定）・`付けない`・`付ける` のどれか。生成前の問いの答えを書く（`questions.md`） |

- 日本語の項目名は引用符で囲む（`"作者" = "…"`）。TOML の裸のキーは英数字しか使えない
- 表にない項目を書くとエラーになる（書き間違いを見つけるため）
- 型の定義が画像の項目（選挙の「地図」など）としていれば、値は本文の画像と同じ `![キャプション](相対の道)` を書く（下記「画像」）。書き出しは定義の書式に従い、`name` はファイル名だけ、`file` は `[[ファイル:…|thumb|キャプション]]` になる。画像ではない項目にこの記法を書くと値がそのまま引数に入るので、検査が `INFOBOX-IMAGE-UNDECLARED` で警告する
- 型の定義にない項目を書きたいときは、`[infobox]` に `_template = "Infobox 人物"` と書き、残りの項目名をそのまま本家の引数名にする。項目の並びは書いた順で、ウィキテキストは `Infobox 人物` の呼び出し（引数を `|` で並べる形）になり、HTML は項目名（本家の表示名）を見出しにした表になる。引数名は本家のテンプレートページで確かめる
- `_template` の原稿は、同梱の TemplateData（本家の引数の定義）と突き合わされる。本家に無い項目名は警告（`INFOBOX-UNKNOWN-FIELD`）、必須の項目の欠けはエラー（`INFOBOX-MISSING`）になる。引数名の揺れ（英語名・別名）は本家の定義から日本語の引数名に寄せる
- ファイル名だけを受け取る引数は `_image_fields = ["画像", "地図"]` に並べる（書かないと `![キャプション](道)` は `[[ファイル:名前|thumb|キャプション]]` として渡る）。`_image_fields` を書かなければ、TemplateData で画像を受け取る引数がファイル名だけの書式になる
- キーは英数字・ハイフン・下線だけ。材料の出典のキー（`history-news-start` など）をそのまま使ってよい
- TOML の並びに注意する。`[[navbox]]` は配列の表なので、そのあとに書いた裸のキー（`stub`・`categories` など）は最後の箱の項目として読まれる。`categories`・`stub`・`[coord]` は `[[navbox]]` より前に書く

### 出典

| 項目 | 必須 | 書くこと |
| --- | --- | --- |
| `kind` | 必須 | `web`（Web のページ）・`book`（書籍）・`news`（新聞・雑誌の記事）のどれか |
| `title` | 必須 | 出典の題。記事なら記事名、書籍なら書名 |
| `url` | 任意 | 開いて確かめた URL。`http://` か `https://` で始まる |
| `author` | 任意 | 著者 |
| `publisher` | 任意 | 発行元（出版社・サイトの運営者） |
| `work` | 任意 | 掲載先（新聞名・雑誌名・サイト名） |
| `date` | 任意 | 公開日・発行日。`YYYY-MM-DD`・`YYYY-MM`・`YYYY` のどれか |
| `access_date` | 任意 | 閲覧日。`YYYY-MM-DD`。Web の出典には必ず書く |
| `isbn` | 任意 | 書籍の ISBN |
| `pages` | 任意 | 参照したページ（`23`・`3-20`） |
| `note` | 任意 | 出典についての短い補足（「同ページの年の表記は誤記と判断し採らない」など） |
| `weak` | 任意 | 弱い出典（攻略 Wiki・個人のブログ・SNS・掲示板・まとめ）なら `true`。使った所には `[!信頼性要検証]` が要る |

- 出典の誤記が疑われるときは、`note` にそう書き、ほかの出典で確かめられた値を本文に使う
- 定義した出典は、本文か注釈で必ず使う。使わない出典はエラーになる（`REF-UNUSED`）

## 本文

- 最初の `## ` 見出しより前が導入部（見出しは付けない）。そのあとが節
- 見出しは `## `（h2）・`### `（h3）・`#### `（h4）。`# ` は使えない。階層を飛ばせない
- 段落は空行で区切る。段落の中で改行してもよい（空白なしでつながる）
- 箇条書きは行頭の `- `。入れ子にはできない。箇条書きのすぐ後に空行なしで段落を続けない
- 表と定義リストは書けない。登場人物は 1 人 1 項目の箇条書き（`- 名前（よみ）: 説明`）か、人物ごとの h3 と段落で書く
- 画像は独立した行に `![キャプション](画像の道)` と書く（下記）
- 節を書きかけで残すときは、節の最後に `[!節スタブ]` を単独の行で書く（段落の中には書けない）
- 末尾の 脚注・参考文献・関連項目・外部リンク・カテゴリの節は書かない。スクリプトが設定欄から組む

文中の記法:

| 書き方 | 意味 |
| --- | --- |
| `[^キー]` | 出典の脚注の印。`[^a][^b]` と並べてよい。句点の前に置く |
| `[^n:キー]` | 注釈の印 |
| `[[記事名]]`・`[[記事名\|表示]]` | 内部リンク（本家の同名の記事へ向く） |
| `'''…'''` | 太字。導入部の第一文の記事名に使う |
| `[!要出典]`・`[!信頼性要検証]` | 点の印（下記） |
| `[!要出典範囲\|文]`・`[!独自研究範囲\|文]` | 範囲の印（下記） |
| `[!原文\|言語タグ\|文]` | 外国語の原文。訳文に添える（下記「外国語の引用」） |
| `[!仮リンク\|言語タグ\|本家の記事名\|表示]` | ほかの言語の記事へのリンク（下記「ほかの言語の記事へのリンク」） |
| `[!言語\|言語タグ]` | 言語名（`en` は「英語」） |
| `[!節スタブ]` | 書きかけの節の印。行に単独で書く（段落の中には書けない） |

## 画像

本文に画像を置くには、行に単独で次のように書く。

```text
![夜の屋台の挿絵](images/yatai.png)
```

- 道は原稿からの相対の道。URL や絶対の道は使えない
- 埋め込めるのは PNG・JPEG・GIF・WebP・SVG で、1 枚 2 MiB まで
- キャプションは空にしない。何の画像かを一文で書く（空だと検査が `IMAGE-CAPTION` で警告する）
- HTML には画像そのものを data: の URI として埋め込むので、HTML 1 枚だけで開ける。ウィキテキストには `[[ファイル:yatai.png|thumb|夜の屋台の挿絵]]` とファイルの名前だけを書き、本家への画像のアップロードは別に行う
- 行の途中に書くと読み取りのエラーになる。段落・箇条書きと同じ「まとまり」として並ぶ
- 画像は原稿と同じフォルダか、その下のサブフォルダに置く
- Infobox の画像の項目（選挙の「地図」など）も、本文と同じ `![キャプション](相対の道)` を `[infobox]` に書く。書き出しは型の定義の書式に従う（`name` はファイル名だけ、`file` は `[[ファイル:…|thumb|キャプション]]`）。どの項目が画像かは型の定義が決める（上記「設定欄」）。宣言していない項目にこの記法を書くと検査が `INFOBOX-IMAGE-UNDECLARED` で警告する
- 選挙の州別の結果の地図や議会の議席の図は、外から画像を取らずに `figure` で作れる（下記「図を作る」）

## 図を作る（地図と議席図）

選挙の州別の結果の地図や、議会の議席の図は、外から画像を取らずに作れる。データを TOML で書き、`figure` で SVG を出す。

```bash
sh <スキルのフォルダ>/scripts/wiki.sh figure map 選挙地図.toml --out 選挙地図.svg
```

- 作った SVG は、本文か Infobox の画像の項目に `![キャプション](選挙地図.svg)` と書いて置く（上記「画像」）
- 種類は `map`（地域を色で塗る）と `seats`（議席を半円に並べる）の二つ。`--out` は必ず付ける
- データか形が正しくないときは「[エラー] FIGURE: …」で終了コード 1、書き出せないときは「[エラー] WRITE: …」で 1

地図のデータ:

```toml
title = "2004年アメリカ合衆国大統領選挙の州別の結果"
shape = "us-states"

[colors]
republican = "#c0392b"
democrat = "#2c5aa0"

[regions]
TX = "republican"
CA = "democrat"
```

- `shape` は塗る元の SVG。同梱は `us-states`（アメリカ合衆国の州。`TX`・`DC` などの 2 文字のコードで塗れる）だけ。ほかの地図は SVG の道を書くか、`--shape` で渡す（`--shape` は `map` だけの指定で、データの `shape` より優先する）。同梱の地図は Commons の CC0 のもの（`assets/maps/README.md` に出典）
- `colors` は色の名前と `#rrggbb`、`regions` は地域と色の名前。`colors` に無い名前や、形に無い地域はエラー。大文字小文字だけ違えば形の側の書き方に合わせる（`tx` は `TX` に当たる）
- 形の SVG は、塗りたい要素に `class`（`tx` のような 3 文字までか `region-tx`）か `data-region="tx"` を付けておく。付いていない要素は塗れない
- ほかに `title`（図の題。`<title>` と読み上げの名になる）・`background`（下地の色。`none`・`transparent` で無し）・`legend`（下に付ける凡例。省くと付ける）が書ける。凡例には使った色だけを `colors` の順で出す

議席図のデータ:

```toml
[[party]]
name = "共和党"
seats = 286
color = "#c0392b"

[[party]]
name = "民主党"
seats = 251
color = "#2c5aa0"
```

- 議席は左から右へ `[[party]]` の順に並ぶ（政党の並びがそのまま左右になる）。下に「合計 N 議席」と凡例を出す
- `seats` は 0 以上の整数。名前の重複・空、色の誤り、合計 0 はエラー。行の数は合計から自動で決まる（指定できない）

## 外国語の引用

外国語の資料の文を引くときは、日本語訳を本文に書き、原文を `（原文：…）` で添える。原文は `[!原文|言語タグ|文]` で包む。

```text
「初期の研究は撮像過程のぼけを無視していた」（原文：[!原文|en|Their work disregarded the blur in the imaging process.]）[^history-paper]
```

- 言語タグは BCP 47 の形（`en`・`en-US`・`zh-Hans`・`ko`・`de`）。形が違う、または文が空だとエラーになる
- 書き出すと、HTML では `<span lang="en">…</span>`、ウィキテキストでは本家の Template:Lang（言語タグと原文を渡すテンプレート）になる。書き出しはスクリプトがするので、テンプレートは書かない。`--style plain` では本家のテンプレートを使わず、タグを付けない文字だけになる
- 原文の文は、和文用の検査（ASCII の引用符・半角のカンマとピリオド・評価語など）にかけない。原文の外の和文は今までどおり検査する
- 脚注の印 `[^キー]` は `[!原文|…]` の外に置く（原文の文に `[^`・`[!`・`[[` は書けない）。太字と範囲の印の中には書けない
- 原文の文は、材料の「原文（逐語）」から写す。要約から写した句は使わない
- ブロック引用（本家の Template:Quotation）には未対応。長い引用も、文の単位で訳と原文を並べる

## ほかの言語の記事へのリンク

日本語版にまだ記事が無いが、ほかの言語の版にはある項目は、`[!仮リンク|言語タグ|本家の記事名|表示]` で書く。

```text
兵器の名称は[!仮リンク|en|M4 Sherman|M4中戦車]として知られる[^history-book]。
```

- 書き出すと、HTML は赤字の内部リンク（`class="new"`）と「（英語）」の外部リンク、ウィキテキストは本家の仮リンクのテンプレート（引数は表示・言語タグ・本家の記事名の順）になる
- 表示は省ける。省くと本家の記事名をそのまま出す（`[!仮リンク|en|M4 Sherman]`）
- 言語タグは BCP 47 の形（`en`・`en-US`・`zh-Hans`）。形が違う、または本家の記事名が空だとエラーになる
- 言語名だけを出したいときは `[!言語|en]` と書く。`en` は「英語」になり、知らないタグはタグのまま出る
- 素の記法（`--style plain`）では、仮リンクは表示の文字だけ（リンクは付けない）、言語名はタグ（`en`）のままになる
- 本家に記事がある項目は、今までどおり `[[記事名]]` の内部リンクにする

## 位置・ナビゲーションの箱・スタブ

位置（座標）・節の下に置くナビゲーションの箱・書きかけの記事のスタブは、設定欄に書くと、書き出しのときに本家と同じ形で付く。

```text
+++
title = "…"
type = "place"
categories = ["…"]
stub = "Japan-geo-stub"

[coord]
lat = 35.681236
lon = 139.767125
type = "city"
display = "title"

[[navbox]]
name = "Cities"
title = "日本の都市"
items = ["東京", "横浜"]
+++
```

- 座標は `lat`・`lon` を十進の度で書く（必須）。南緯・西経は負の数でよい。`type` は本家の GeoHack の種類（`city`・`mountain`・`island` など）、`display` は本家の表示（`title`・`inline`・`dms`・`inline,title`。既定は `title`）
- 座標を書くと、HTML は導入部の先頭に「座標: 北緯35度40分52秒 東経139度46分02秒」の行（本家の GeoHack へのリンク付き）、ウィキテキストは先頭の座標テンプレート 1 行になる。緯度経度は丸めない（十進のまま渡す）
- ナビゲーションの箱は末端の節の下（外部リンクの後・カテゴリの前）に、書いた順で並ぶ。`items` の項目は箇条書きになり、`name` と `state` はウィキテキストにだけ出す（HTML では使わない）
- スタブは書きかけの記事に 1 つ。値はそのまま本家のテンプレート名になる
- 素の記法（`--style plain`）では、座標は「座標: 北緯…東経…」の行、箱は太字の題と箇条書き、スタブは「この記事は書きかけです。」の文、節スタブは「この節は書きかけです。」の文になる
- TOML の並びに注意する（上記「設定欄」）。裸のキー（`stub`・`categories`）と `[coord]` を先に、`[[navbox]]` を最後に書く


## 印と警告の枠

確かめられなかった事実は落とさず、本家と同じ印を付けて載せる。書き出すと、HTML では上付きの `[要出典]` などに、ウィキテキストでは本家の同じ名前のテンプレート（日付つき）になる。

| 書き方 | 使う所 | 例 |
| --- | --- | --- |
| `[!要出典]` | 元を特定できない事実の文の後（脚注は付けない） | `屋台の名前は作者の地元の店から取られた[!要出典]。` |
| `[!信頼性要検証]` | 弱い出典（`weak = true`）の脚注の印のすぐ後 | `連載の前に読み切りが描かれた[^history-fanwiki][!信頼性要検証]。` |
| `[!要出典範囲\|文]` | 出典の無い範囲を包む | `[!要出典範囲\|当時は屋台の数が減っていた]。` |
| `[!独自研究範囲\|文]` | 出典で確かめられていない見方・推測の範囲を包む（主に wiki-with-rumor） | `[!独自研究範囲\|運営の縮小の原因をコラボに求める見方が出た][^impact-matome][!信頼性要検証]。` |

- 弱い出典の脚注の印の後に `[!信頼性要検証]` が無いと、検査がエラーにする（`REF-WEAK-UNMARKED`）
- 範囲の印の中には、文字・内部リンク・脚注の印を書ける。太字と印の入れ子は書けない
- 印のある記事には、冒頭に警告の枠が自動で付く。`要出典`・`要出典範囲`・`信頼性要検証` からは「出典の明記」、`独自研究範囲` からは「独自研究」。付け方は設定欄の `notice_rule` に従う。既定の `多いときだけ` では、その種類の印が、脚注の印と印を合わせた数の 2 割以上のときだけ付ける（脚注 20・`要出典` 2 なら付けず、5 なら付ける）。`付けない` なら付けず、`付ける` なら印が一つでも付ける。印から決まらない枠（噂・考察を載せた記事の「観点」など）は、設定欄の `notices` に書く。枠が二つ以上なら一つの枠にまとまる

### 噂の印（wiki-both だけ）

`wiki-both` は、1 本の原稿から「通常の記事」と「噂込みの記事」の二つの版を書き出す。噂・考察の所に次の印を付ける。`wiki` と `wiki-with-rumor` では使わない。

| 書き方 | 意味 |
| --- | --- |
| `[!噂\|文]` | 噂・考察の範囲。通常の記事では範囲ごと消え、噂込みの記事では中身だけが残る。中には文字・内部リンク・脚注の印・点の印・範囲の印・原文 `[!原文\|…]` を書ける（`[!噂\|…]` の入れ子は不可） |
| 見出しの末尾の ` [!噂]` | 節ごと噂・考察（例 `## 騒動 [!噂]`）。通常の記事では、その節と子の節が消える |

- 段落や箇条の項目が `[!噂\|…]` 一つだけでできていれば、通常の記事ではそのまとまりごと消える
- 文の単位で包み、句点「。」も範囲の中に入れる（例 `前の文。[!噂\|噂の文[^impact-matome][!信頼性要検証]。]`）。句点を外に置くと、通常の記事で「。。」が残る
- 通常の記事で使われなくなった出典は、通常の記事の出典の一覧から自動で外れる
- 噂込みの記事には「観点」の枠が自動で付く。設定欄の `notices` に `観点` は書かない
- `check` と `build` は二つの版の両方を検査し、`build` は `<原稿の名前>.html`（二つの版を切り替えられる 1 枚）・`<原稿の名前>.wikitext`（通常）・`<原稿の名前>.噂込み.wikitext`（噂込み）を書き出す


## コマンド

```bash
sh <スキルのフォルダ>/scripts/wiki.sh type [類型の ID]
sh <スキルのフォルダ>/scripts/wiki.sh fetch <URL> [--max-chars 字数] [--offset 字数]
sh <スキルのフォルダ>/scripts/wiki.sh check 原稿.md
sh <スキルのフォルダ>/scripts/wiki.sh build 原稿.md [--style plain] [--out-dir 出力先] [--updated 日時]
sh <スキルのフォルダ>/scripts/wiki.sh figure <種類> <データ>.toml --out <図>.svg [--shape <形>]
```

- `type`: ID が無ければ類型の一覧、あれば設定欄に貼る `type` と `[infobox]` の雛形を出す
- `fetch`: Web のページを取り、題と本文の文字を出す。WebFetch で取れないページ（web.archive.org の保存版など）に使う（`research.md` の「ページの取り方」）。取れなければ終了コード 1
- `check`: 検査だけして、指摘を 1 行 1 件で出す（`12 行目 [警告] WORD-PUFFERY: …`）。最後に件数のまとめ
- `figure`: 地図（`map`）か議席図（`seats`）の SVG を作る（上記「図を作る」）。原稿に載せる図を外から取らずに済ませる
- `build`: 検査を通ったら、原稿の隣に `<原稿の名前>.html` と `<原稿の名前>.wikitext` を書き出す。`--style plain` はウィキテキストを本家のテンプレートを使わない素の記法で書く。`--updated` を省くと、最終更新の日時に今の現地時刻を入れる

| 終了コード | 意味 | 次の一手 |
| --- | --- | --- |
| 0 | 書き出した（`check` ならエラーが無かった）。警告があっても 0 | 警告を読み直す |
| 1 | 原稿にエラーがあって書き出していない（`figure` では図を描けなかった） | 指摘の行を直して流し直す |
| 2 | 呼び方の誤り（引数・原稿のファイル・類型の ID） | 呼び方を直す |
| 3 | Python 3.11 以上が見つからない | 利用者に Python か uv を入れてもらう。案内の文が標準エラーに出る |

`wiki.sh` は、`python3`・`python`・`py -3`・`uv` の順に Python 3.11 以上を探す。Python が分かっているなら `python <スキルのフォルダ>/scripts/wiki.py build 原稿.md` でも流せる。
