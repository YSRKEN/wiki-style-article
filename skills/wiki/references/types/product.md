# 製品（`product`）

工業製品・食品・乗り物・ソフトウェア・Web サービスなど、メーカーや運営者が世に出した製品を題材にする型。細かい種類: `food-drink`（食品・飲料）、`railcar`（鉄道車両）、`aircraft`（航空機）、`automobile`（自動車）、`software`（ソフトウェア）、`web-service`（Web サービス）。節の並びはこのファイルに従い、Infobox だけが変わる。Infobox の項目は `sh wiki.sh type product` で原稿の雛形を出せる。

## 節の並び

既定は工業製品の並び「沿革 → 構造・特徴 → 型式構成 → 運用／販売 → 評価 → 主要諸元」。食品・飲料は並びが違う（下の差分を見る）。

1. 概要: 製品の位置づけを要約する（題材しだい。置かずに「沿革」から始める記事もある）。
2. 沿革（歴史）: 開発の背景から現在まで。時期ごとに小節を分ける。
3. 構造・特徴: 仕組みや仕様。節名は「特徴」「構造」「メカニズム」「機体の特徴」のように題材に合わせる。「製法・仕組み」という節名は使わない。
4. 型式・シリーズ構成: 「シリーズ構成」「形式構成」。型ごとに小節を立てる。
5. 運用・販売: 運用者、販売数、普及の状況。乗り物なら「運用の状況・特徴」。
6. 評価・影響: 節名は「評価」「評価・影響」。「社会的反響」とはしない。
7. 事故・不具合（資料があれば）: 乗り物なら「主な事故・事件」。
8. 主要諸元（工業製品）: 寸法・重量・性能などの数値を、1 項目 1 行の箇条書きで書く（原稿は表を書けない）。
9. 関連（資料があれば）: 広告（CM）、コラボレーション商品、関連作品。

「沿革」を先に置く記事と、「特徴・構造」を先に置く記事に割れる。材料から決め手が出ないので、沿革を先にする既定を使い、題材が特徴の説明から入るほうが自然（食品など）ならそちらにする。

## 導入部

```
'''製品名'''（原語）は、メーカーが開発・製造・販売する{種類}。
```

- 製品名を『』で囲まない（作品の記事とは違う）。
- 乗り物は用途と形式（「長距離路線向けのワイドボディ4発ジェット旅客機」）、食品は発売年と販売元を第一文に入れる。
- 現役でない製品は「かつて〜に在籍していた」「〜まで製造していた」と、運用の終わりを第一文に入れる。
- 第二段落以降で、特徴的な仕様、歴史の要約、評価を述べる。商標や略称に触れることがある。
- 範囲を限る一文（「本項では〜についても記述する」）や、略称の約束（「以下、Aと表記」）を導入部に置く記事がある。
- 乗り物の記事は導入部に出典を多く付ける。

## 調べる観点の下敷き

- 基本情報（種類・メーカー・発売年・後継）: メーカー・運営者の公式サイト、製品情報、報道発表。
- 開発の背景と歴史: 社史、開発者の証言、専門誌・新聞の記事、書籍。
- 構造・特徴・仕様: カタログ、公式の技術資料、専門誌、書籍。数値は出典ごとの違いも確かめる。
- 型式・シリーズ・バージョンの構成: メーカーの型式一覧、専門書、運用者の資料。
- 運用・販売・普及（販売数・売上・運用者・保存状況）: 公的な統計、運用者の公表資料、有価証券報告書などの企業資料。
- 評価・受賞・影響: 専門誌の評価、新聞・雑誌の論評、受賞の記録。メーカーの自己評価は評価の出典にしない（R130）。
- 事故・不具合・論争: 調査報告書、報道、判決。
- 広告・文化（CM、コラボ商品、関連作品）: 広告の記録、報道、作品そのもの。

題材しだいで、構造・特徴と型式構成は1人にまとめる。沿革が長い製品は、時期ごとに担当を分ける。

## この類型の作法

- 製品の記事は、メーカーと関係のない第三者が公表した資料で検証できることを土台にする。メーカーの発表やプレスリリースだけを根拠にしない（R130）。
- 「画期的な」「業界を代表する」のような評価語を地の文に置かない。販売数・受賞・順位などの事実で示す（R131）。
- 販売価格・仕様・リリースノートを逐一並べない（R132）。主要諸元は要点の数値に絞る。
- 脚注は数値（販売数、売上、諸元）に多く付ける。
- 節名は、「商品構成」「広告」「社会的反響」ではなく、「シリーズ構成」「形式構成」「CM」「評価」を使う。
- 運用を終えた製品は過去形で書く。

## 細かい種類の差分

- `food-drink`（食品・飲料）: 特徴（味／原材料／パッケージ）→ 歴史（背景／開発／発売後／リニューアル／年表）→ 容器・包装 → 栄養素 → 評価 → 活用・その他 → CM → コラボ商品。特徴を先に置く。導入部の第一文に発売年と販売元を入れる。
- `railcar`（鉄道車両）: 概要 → 導入経緯（開発の背景）→ 車体 → 主要機器 → 沿革・変遷 → 運用 → 保存車両 → 編成表。沿革は後ろに置く。「主要諸元」の節は作らず、数値は Infobox に集める。第一文は `'''形式名'''（読み）は、{事業者}が{年（和暦）}に導入した{用途}の{電車／電気機関車}である。`、年は丸括弧の和暦。技術的な位置づけを次の文で書き、導入部に出典を多く付ける。
- `aircraft`（航空機）: 旅客機は 概要 → 沿革 → 機体の特徴 → シリーズ構成 → 運用の状況・特徴 → 主な事故・事件 → 主要諸元。軍用機は 概要 → 開発の経緯 → 型 → 性能 → 実戦 → 現存する機体 → 性能諸元 → 登場作品。第一文は `'''機種名'''（原語）は、{メーカー}が開発・製造した{種類}である。`、軍用機は所属と来歴を続ける。主な事故・事件は、航空の指針（草案）に沿って、死者が出たもの、機体が失われたもの、手順や規則の変更に至ったものに絞る。主要諸元は 1 項目 1 行の箇条書きで書く（原稿は表を書けない）。
- `automobile`（自動車）: 秀逸・良質の見本が無く、型として固まっていない。複数世代の車種は 概要 → 世代ごとの節（「N代目 型式（YYYY年 - YYYY年）」）→ モータースポーツ → 車名の由来。単一世代の車種は 概要 → 開発 → メカニズム → デザイン → グレード。導入部は1〜2段落で短く、派生車種が多いときは範囲を限る一文を置く。
- `software`（ソフトウェア）: 概要・特徴 → 設計・仕組み → 歴史 → ライセンス。歴史を前に置く記事と後ろに置く記事がある。導入部は `'''名'''（略称）とは、{種別}である。` か `は、{開発元}によって開発されている{種別}である。`。名称の誤解を先に解く文や、狭義と広義の語義を分ける文を続けることがある。見本が少ない。
- `web-service`（Web サービス）: 沿革 → 特徴・機能 → 評価・受賞。大きなサービスは「利用者数」「収益」「文化」「諸問題」が加わる。第一文に運営者と種別を入れ、サービス開始時期と規模を数字で続ける。規模・利用者数は「YYYY年M月現在」と時点を付ける。見本が少ない。
