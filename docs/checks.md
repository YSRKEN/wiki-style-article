# 原稿の検査

AI が書いた原稿を読み取った結果（[原稿の書き方](source-format.md)）を検査して、**エラー**と**警告**の一覧を返す。実装は `plugins/wiki-style-article/skills/wiki/scripts/wikiskill/checks/`。

```python
from wikiskill import read_article_file
from wikiskill import load_default_registry
from wikiskill.checks import check_article

for finding in check_article(read_article_file("原稿.md"), load_default_registry()):
    print(finding)  # 15 行目 [エラー] REF-UNDEFINED: 脚注の印 [^x] に対応する …
```

第二引数は類型の定義（`wikiskill.load_default_registry()`）。渡すと、原稿の `type` と Infobox を定義と突き合わせる規則（下の E）も検査する。省くとその規則だけが動かず、ほかの規則は同じに動く。

`check_article` は `Finding(level, rule, message, line)` の並びを、行番号の昇順（同じ行ではエラーが先、あとは規則の ID の順）で返す。

- **エラー**: 直すまで原稿を渡さない。誤検出しにくい作法の違反だけを入れる
- **警告**: 誤検出しうる作法。一覧で示し、AI が前後を読み直して、直すか残すかを決める

## 振り分けの原則（2026-11-02、依頼者の決定）

誤検出しにくい作法は止める（エラー）。評価語・婉曲のように誤検出しうる作法は警告にとどめる。この担当では、規則ごとに次の問いで振り分けた。

1. **見つかった文字が、ほぼ必ず書き間違いと言えるか。** 印と定義の突き合わせ、書式、ホスト名、全角空白のように、正当な使い道がほぼ無いものはエラー
2. **作品名・固有名詞・引用に正当な例外があるか。** 例外があるもの（波ダッシュ、ローマ数字、「ヶ」、敬称、「…」）は、書き間違いと言い切れないので警告
3. **語の出現だけでは良し悪しが決まらないか。** 評価語・婉曲・古くなる表現は文脈で正当になる（引用、時点つきの「現在」など）ので警告
4. 決めきれないものは警告に倒す

警告の規則は、引用やせりふ（`「」`）と、作品名にあたる部分（`『』`・内部リンクの表示・太字）の中の一致を見逃す。エラーの規則は題名の中でも見逃さない（全角空白は作品名でも直すべきため）。

## 検査の対象と限界

- 本文（導入部・節の段落と箇条書き）、節の見出し、Infobox の値、注釈の本文を、記法を取り除いた「画面に出る文字」として検査する。出典の題・著者などの項目は、出典の規則（下の A）だけが見る
- 行番号は、段落なら**段落の先頭の行**、箇条書きなら**項目の先頭の行**を指す。段落の中で複数行にまたがる文でも、指摘の文面に前後の文字を添えるので、そこから探す
- 同じ行・同じ規則・同じ文字の指摘は一件にまとめる
- Infobox の項目の検査（下の E）は、類型の定義（`registry`）を渡したときだけ動く。読み取り結果は `type` の行と `[infobox]` の見出しの行を持たないので、`TYPE-UNKNOWN` は冒頭の行（1 行目）、`INFOBOX-MISSING` は Infobox の最初の項目の行（項目が無ければ 1 行目）を指す
- 敬称「氏」「様」「先生」は検出しない（藤原**氏**・多**様**・同**様**・**先生**のように、人名の敬称でない用法が多く、警告が埋もれる）。「さん」と「（故人）」だけを見る

## 規則の一覧

### A. 出典と脚注（エラー中心）

| ID | レベル | 内容 | 誤検出の例・振り分けの理由 |
| --- | --- | --- | --- |
| `REF-UNDEFINED` | エラー | `[^キー]` に対応する `[refs.キー]` が無い | 突き合わせなので誤検出が無い |
| `NOTE-UNDEFINED` | エラー | `[^n:キー]` に対応する `[notes.キー]` が無い | 同上。出典と注釈は別の名前空間で、`[^a]` があっても `[^n:a]` は通らない |
| `REF-UNUSED` | エラー | 定義した出典が本文にも注釈にも一度も使われていない | 注釈の本文で使った出典は「使用済み」と数える。使わない出典は出力で「出典」の節に孤立するため、止める |
| `NOTE-UNUSED` | エラー | 定義した注釈が本文で使われていない | 同上 |
| `REF-WIKIPEDIA` | エラー | `url` のホストがウィキペディア（他言語版・モバイル版を含む）またはその転載サイト | 下の「ホスト一覧」。ホスト名の完全一致（サブドメインを含む）で、`example.com/wikipedia.org` や `notwikipedia.org` は通る |
| `REF-WIKIPEDIA-NAME` | 警告 | 題・発行元・`work` に「Wikipedia」「ウィキペディア」「フリー百科事典」がある（`url` がウィキペディアでない場合） | ウィキペディアを扱った書籍の題（例: 『Wikipedia: The Missing Manual』）は正当に引っかかるため警告 |
| `REF-URL` | エラー | `url` が `http://` か `https://` で始まるアドレスでない（ホスト無し・空白入り・`ftp:` など） | 書式の検査 |
| `LINK-URL` | エラー | 外部リンクの `url` が同じ条件を満たさない | 同上。行は `[[external_links]]` の見出し |
| `REF-DATE` | エラー | `date` が `YYYY-MM-DD`・`YYYY-MM`・`YYYY` のどれでもない、または実在しない日付 | 書籍や記事は年月までしか分からないことがあるので年・年月も許す。`2020/09/01`・`2020-9-1`・`2023-02-29` はエラー |
| `REF-ACCESS-DATE` | エラー | `access_date` が `YYYY-MM-DD` でない、または実在しない日付 | 閲覧日は日まで分かる。今日より後の日付かは時計に依存するので見ない |

#### ホスト一覧

根拠は日本語版の方針「Wikipedia:検証可能性」の節「ウィキペディア自身及びウィキペディアの転載サイト」（WP:CIRCULAR、版 2025-06-18）。「ウィキペディアプロジェクトの記事自身やウィキペディアのミラー記事サイトを記事のソースとして用いてはなりません」とある。「Wikipedia:信頼できる情報源」（版 2026-08-30）も、他言語版を含むウィキペディア自身の引用を自己言及としてできないとし、ウィキで構築されたサイトへの投稿は使えないとしている。

転載サイトの一覧は「Wikipedia:ウィキペディアを情報源とするサイト」（版 2026-10-24。載っているサイトの多くはサービス終了）から、転載が主なサイトを選んだ。`wikipedia.org`・`wikiwand.com`・`wapedia.mobi`・`wiki5.ru`・`wpanda.net`・`findwiki.info`・`jibiki.info`・`wikipedia.7val.com`（`checks.references.WIKIPEDIA_HOSTS`）。一覧の Weblio（`www.weblio.jp`）は、ウィキペディアの写しを他の辞書と同じ `www.weblio.jp/content/<語>` に並べており、ホスト名では見分けられない。ウィキペディアの写しだけを指す `weblio.jp` の `/wkpja/` で始まる URL（`/content/<語>` へ転送される形）だけを対象にした（`checks.references.WIKIPEDIA_PATHS`。2026-11-02 に確かめた）。`wikimedia.org`（コモンズなど）は記事ではないので対象外。

### B. 表記（Wikipedia:表記ガイド）

| ID | レベル | 内容 | 誤検出の例・振り分けの理由 |
| --- | --- | --- | --- |
| `FULLWIDTH-SPACE` | エラー | 全角空白 `　`（段落頭の字下げ、位置合わせとも） | 表記ガイドが使わないとする（字下げ・位置合わせとも）。題名の中でも直す |
| `HALFWIDTH-KANA` | エラー | 半角カナ `ｱｲｳ` | 同上 |
| `FULLWIDTH-ALNUM` | エラー | 全角の英数字 `ＡＢＣ１２３` | 半角にそろえる。固有名詞の例外は実在するが、AI が書く文には現れにくい |
| `FULLWIDTH-PUNCT` | エラー | 全角のカンマ・ピリオド `，．` | 和文の句読点は「、」「。」 |
| `REPEATED-PUNCT` | エラー | `。。`・`、、` | 重ねる使い方が無い。「……」は別 |
| `ZERO-PAD-DATE` | エラー | `01月`・`05日` のような 0 詰めの日付 | `2016年10月`・`100日間`・`01日本橋`（`日本`の前）は引っかからない |
| `ZERO-PAD-TIME` | 警告 | `03時`・`05分` のような 0 詰めの時刻 | `05分科会`・`03分隊`のような別の語に当たるので警告 |
| `SLASH-DATE` | 警告 | `2003/02/01`・`2003-02-01` と書いた年月日 | 作品名や引用に現れうるので警告 |
| `ELLIPSIS` | 警告 | `・・・`・`...`・単独の `…` | `……`（2 つ重ね）は通る。作品名（`『…』`）・リンク・太字の中は見逃す |
| `WAVE-DASH` | 警告 | 波ダッシュ `〜`・全角チルダ `～` | 作品名・固有名称の正式な表記にあるので警告 |
| `DASH` | 警告 | ダッシュ `—`・`―` | 同上。長音符 `ー` は別なので引っかからない |
| `SYMBOL-NUMERAL` | 警告 | ローマ数字 `Ⅳ`・丸数字 `①`・全角 1 字の略記号 `㈱`・`㎝` | 固有名詞の正式名称は例外と表記ガイドが認めるので警告。ASCII の `IV` は通る |
| `SMALL-KE` | 警告 | `ヶ` | 茅ヶ崎・三ヶ日・鎌ヶ谷のような固有名詞で正しい。警告にとどめ、「1ヶ月」を「1か月」に直す |
| `HONORIFIC` | 警告 | 漢字・カタカナの後ろの `さん`、`（故人）` | 『サザエさん』のような作品名（`『』`・`「」`・リンク・太字の中）は見逃す。ひらがなの名前（ほたるさん）は見ない。漢字の後ろの `さん` は人名かどうか区別できないので `お父さん` も引っかかる |
| `POLITE-STYLE` | 警告 | 文末の `です`・`ます`・`でした`・`ました` など | せりふ（`「」`）の中は見逃す。「だます」のような動詞の終止形は引っかかる |
| `DIGIT-COMMA` | 警告 | `1,000,000` のような 3 桁区切り | 財務・製図では許される。「万」「億」の区切りを基本にする |
| `ASCII-QUOTE` | 警告 | 和文の `" "` や `“ ”` | 英語の語句の引用は正当なことがある |

### C. 言葉の選び（すべて警告）

語の出現は文脈で正当になる（引用、時点を書いた「現在」、固有名詞）ので、すべて警告にして AI が読み直す。語の一覧は `checks/wording.py` にある。

| ID | 内容（根拠） | 誤検出しやすい例 |
| --- | --- | --- |
| `WORD-PUFFERY` | 評価語（重要な・非常に・極めて・屈指・傑作・名作など）。事実で示す（大言壮語をしない） | `重要文化財`（`重要な`ではない）は通る。「非常に」は中立な文にも出る |
| `WORD-HEDGE` | 主語のない伝聞・婉曲（と言われている・と考えられる・知られている・だろう・かもしれない・〜らしい など）（言葉を濁さない） | `素晴らしい`・`子供らしい`・`彼女らしい`の `らしい` は通る。「として知られる」は日本語版でも使われる |
| `WORD-AVOID` | 読者の知識の決めつけ・自慢の含み（もちろん・当然・いわゆる・を誇る・基本的に など）（避けたい言葉。草案のため弱い） | 「当然」は論理の接続でも出る |
| `WORD-STALE` | すぐ古くなる時点表現（最近・近年・現在・今のところ・現時点 など）（すぐに古くなる表現は使わない） | `2026年11月現在`・`現在の福岡県`・`現在形`・`最近傍`・`最近接`は通る |
| `WORD-JAPAN-CENTRIC` | 我が国・本邦・邦人・我々・世界的に（日本中心にならないように。試行中） | `日本国内`は通る |
| `KANA-OPEN` | 仮名で書く語が漢字になっている（或いは・及び・又は・但し・殆ど・所謂 など）（表記ガイド） | 動詞の「及ぶ」の連用形「及び」は引っかかる（警告で読み直す） |

### D. 構造

| ID | レベル | 内容 | 誤検出の例・振り分けの理由 |
| --- | --- | --- | --- |
| `EMPTY-SECTION` | エラー | 本文も子の節も無い節 | 見出しだけの節は未完成。子の節だけを持つ親の節は通る |
| `SELF-LINK` | エラー | 内部リンクの記事名が、この記事の題と同じ | 自己リンクは作らない（スタイルマニュアル/導入部）。完全一致だけを見るので、曖昧さ回避の括弧つきの別記事は通る |
| `LEAD-NO-BOLD` | 警告 | 導入部の最初のまとまりに太字が無い | 記事名を太字にするのが作法だが、題名の言い換えを使う記事もあるので警告。導入部が空なら出さない |
| `TRIVIA-SECTION` | 警告 | 節の名前が「トリビア」「豆知識」「余談」「雑学」「小ネタ」「その他」「エピソード」「備考」など | 作品の「エピソード」（各話）は正当なことがある。`その他の作品`は通る |

### E. 類型と Infobox（類型の定義を渡したときだけ）

| ID | レベル | 内容 | 誤検出の例・振り分けの理由 |
| --- | --- | --- | --- |
| `TYPE-UNKNOWN` | エラー | 原稿の `type` が類型の定義にない ID | 突き合わせなので誤検出が無い。これが出たら Infobox の検査はしない（どの定義と比べるか決まらない） |
| `INFOBOX-MISSING` | エラー | 類型の必須の項目が `[infobox]` にない（値が空白だけの項目も無いものとする） | 突き合わせなので誤検出が無い。定義の `title_field` の項目は、無ければ書き出しが記事名で埋めるので欠けとしない。Infobox を持たない型では出さない。項目ごとに一件 |
| `INFOBOX-UNKNOWN-FIELD` | 警告 | 定義にない項目名が `[infobox]` にある。Infobox を持たない型に項目を書いたときも出す | 書き出しは定義にない項目を本家のテンプレートの引数に写せず、捨てるしかないので直したい。ただし定義の項目の一覧はまだ全部ではなく（番号つきの引数などを収録していない）、正しい項目でも引っかかりうるので警告にとどめる。見本の「連載期間」は、定義の漫画では「発表期間」なので実際に引っかかる |

## 規則を足すとき

1. 試験を先に書く（`tests/test_checks_*.py`。引っかかる例と、誤検出しやすい例の両方）
2. 文字を探す規則は `checks/notation.py`・`checks/wording.py` の表に `Pattern` を足す。構造や突き合わせは `checks/structure.py`・`checks/references.py`、類型の定義との突き合わせは `checks/infobox.py` に関数を足す
3. この表に、ID・レベル・誤検出の例・振り分けの理由を書く
