# 原稿の書き方

記事の原稿は、冒頭の TOML の設定欄と、Markdown 風の本文でできた一つのファイル。HTML とウィキテキストは、どちらもこの原稿から書き出す（[ADR 0001](adr/0001-article-source-generates-both-outputs.md)）。読み取りは `plugins/wiki-style-article/skills/wiki/scripts/wikiskill/` の `read_article` / `read_article_file` が行い、記事を変更できないデータ（`wikiskill.model.Article`）にして返す。

見本は `tests/fixtures/sample_article.md`（架空の漫画の記事）。

## ファイルの形

- 文字コードは UTF-8。改行コードは問わない
- 1 行目を `+++` だけの行にし、次の `+++` だけの行までを設定欄とする。その後が本文
- 設定欄が `+++` で始まっていない、または閉じていないときはエラー

```text
+++
title = "星屑ラーメン"
type = "manga"
+++
'''星屑ラーメン'''は、…

## 概要

…
```

## 設定欄（TOML）

| 項目 | 必須 | 型 | 内容 |
| --- | --- | --- | --- |
| `title` | 必須 | 文字列 | 記事名 |
| `type` | 必須 | 文字列 | 類型の ID。英小文字とハイフン（例 `person-living`, `manga`, `meme`。一覧は [types.md](types.md)）。値が実在の類型かは読み取りでは見ない |
| `reading` | 任意 | 文字列 | 読み仮名（平仮名） |
| `defaultsort` | 任意 | 文字列 | 並べ替えの読み |
| `categories` | 任意 | 文字列の配列 | カテゴリ名 |
| `[infobox]` | 任意 | 表 | 項目名 → 値（文字列）。書いた順を保つ。`_template` を書くと本家のテンプレートをそのまま使う（下の「任意のテンプレート」） |
| `[refs.<キー>]` | 任意 | 表 | 出典。キーは英数字・ハイフン・下線 |
| `[notes.<キー>]` | 任意 | 表 | 注釈。キーは出典と同じ規則 |
| `related` | 任意 | 文字列の配列 | 関連項目の記事名 |
| `[[external_links]]` | 任意 | 表の配列 | 外部リンク |
| `[coord]` | 任意 | 表 | 記事の座標。`lat`・`lon` が必須（下の「座標・ナビゲーションの箱・スタブ」） |
| `[[navbox]]` | 任意 | 表の配列 | 記事の末尾に置く表。`title` が必須 |
| `stub` | 任意 | 文字列 | 記事の末尾に置く書きかけの印のテンプレート名 |
| `notices` | 任意 | 文字列の配列 | 冒頭に貼る警告の枠。使える値は `観点`・`出典の明記`・`独自研究` だけ（下の「警告の枠」） |
| `notice_rule` | 任意 | 文字列 | 印から決まる枠の出し方。`多いときだけ`（既定）・`付けない`・`付ける` のどれか（下の「警告の枠」） |

上の表にない項目を書くと、書き間違いを見つけるためにエラーにする。

### `[infobox]`

値はすべて文字列で、数値も引用符で囲む。TOML の裸のキーは ASCII しか使えないので、**日本語の項目名は引用符で囲む**。

```toml
[infobox]
"ジャンル" = "グルメ漫画"
"連載期間" = "2020年4月 - 2023年3月"
```

#### 任意のテンプレート（`_template`）

型の定義にない項目を書きたいときは、`[infobox]` に `_template` を書き、残りの項目名をそのまま本家のテンプレートの引数名にする。数千ある本家のテンプレートを型ごとに書き写さずに済ませるための抜け道。

```toml
[infobox]
_template = "Infobox 人物"
"氏名" = "山田 太郎"
"生年月日" = "1990年1月1日"
```

- 値は本家の書き方のまま文字列で書く。ウィキテキストは `{{Infobox 人物|氏名 = 山田 太郎|…}}` になり、HTML は項目名を見出しにした表になる（caption は記事名）
- 項目の並びは書いた順。型の定義の `fields` は使わず、`_template` は表に出さない
- `_image_fields = ["画像", "地図"]`（任意）に並べた引数は、本家がファイル名だけを受け取る引数として扱い、ウィキテキストはファイル名だけ（`| 画像 = 顔.png`）にする。`![キャプション](道)` のキャプションは捨てる。書かないときは `[[ファイル:名前|thumb|キャプション]]` になるので、本家のテンプレートページでその引数が `File:` を包むかどうかを確かめる
- `_image_fields` を書かないときは、同梱の TemplateData（下の「TemplateData」）から画像を受け取る引数を引き、ファイル名だけの書式として扱う。書いたときは足さない（明示が優先）
- 検査は型の定義ではなく、同梱の TemplateData（`assets/templatedata.toml`、本家の 86 テンプレート）と突き合わせる。同梱に無いテンプレートは検査しない。定義に無い項目名は `INFOBOX-UNKNOWN-FIELD`（警告）、必須の引数が無いときは `INFOBOX-MISSING`（エラー）。`INFOBOX-IMAGE-UNDECLARED` は出ない（画像の引数は TemplateData から引くため）。同梱の取り方と増やし方は [コマンドの入口](cli.md#templatedata) を参照
- 引数名は本家のテンプレートページ（例 `Template:Infobox 人物`）で確かめる。`_template` の値に `{` `}` `|` `[` `]` と改行は書けない（空にもできない）

### `[refs.<キー>]`（出典）

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `kind` | 必須 | `web` / `book` / `news` のどれか |
| `title` | 必須 | 出典の題 |
| `url`・`author`・`publisher`・`work`・`date`・`access_date`・`isbn`・`pages`・`note` | 任意 | いずれも文字列 |
| `weak` | 任意 | 真偽値（`true` / `false`、引用符で囲まない）。既定は `false`。`true` は弱い出典（攻略 Wiki・個人のブログ・SNS・まとめなど、本家が出典として認めない出どころ）であることを表す |

`url` は `http://` か `https://` で始まるアドレス。`date` は `YYYY-MM-DD`・`YYYY-MM`・`YYYY` のどれか、`access_date`（閲覧日）は `YYYY-MM-DD`（どちらも 0 詰めの半角で、実在する日付）。読み取りではこれらの形を見ず、検査（[checks.md](checks.md)）が見る。ウィキペディアとその転載サイトを `url` に書くとエラーになる（弱い出典でも同じ）。

弱い出典を指す印の直後には `[!信頼性要検証]` を付ける（`…という[^wiki][!信頼性要検証]。`）。間に続く出典の印は挟んでよい。付けないと検査（`REF-WEAK-UNMARKED`）がエラーにする。

### `[notes.<キー>]`（注釈）

`text`（必須、文字列）に注釈の本文を書く。本文と同じ文中の記法（次節）が使える。

### `[[external_links]]`（外部リンク）

`title` と `url` がどちらも必須（文字列）。`[[external_links]]` を繰り返して並べる。

## 本文

最初の `## ` 見出しより前が導入部（見出しなし）で、そのあとが節。

- 見出しは `## `（h2）・`### `（h3）・`#### `（h4）。`# ` は使えない。`#` のあとに空白が必要で、`#タグ` のような行は本文になる
- 見出しの階層は飛ばせない。h3 は直前の h2 の下にだけ、h4 は直前の h3 の下にだけ置ける
- 見出しの末尾の ` [!噂]` は、節ごと噂にする印（下の「噂」）。見出しの文字からは取り除く
- 段落は空行で区切る。段落の中の改行は、日本語のため空白なしでつなぐ
- 箇条書きは行頭の `- ` で始まる行の連なり。入れ子にはできない。字下げした行は前の項目の続きになる。年表や作品の一覧のために使う
- 箇条書きの直後に、空行なしで段落を続けることはできない
- 行頭・行末から取り除くのは半角の空白とタブだけ。全角空白の字下げは本文に残し、検査（`FULLWIDTH-SPACE`）がエラーにする

### 文中の記法

| 書き方 | 意味 |
| --- | --- |
| `[^キー]` | 出典への脚注の印。`[^a][^b]` と並べてよい |
| `[^n:キー]` | 注釈への印 |
| `[[記事名]]`・`[[記事名\|表示]]` | 内部リンク |
| `'''…'''` | 太字。導入部の第一文の記事名に使う。中に内部リンク・脚注の印・点の印を入れてもよい |
| `[!要出典]`・`[!信頼性要検証]` | 点の印。文の直後に付ける（下の「印」） |
| `[!要出典範囲\|範囲の文]`・`[!独自研究範囲\|範囲の文]` | 範囲の印。範囲の文を包む（下の「印」） |
| `[!噂\|範囲の文]` | 噂の範囲。通常の記事では取り除き、噂込みの記事では残す（下の「噂」） |
| `[!原文\|言語タグ\|文]` | 外国語の原文（下の「外国語の原文」） |
| `[!仮リンク\|言語タグ\|本家の記事名]`・`[!仮リンク\|言語タグ\|本家の記事名\|表示]` | 本家の他の言語版にだけある記事へのリンク（下の「座標・ナビゲーションの箱・スタブ」） |
| `[!言語\|言語タグ]` | 言語の名前（`en` → 英語） |
| `[!節スタブ]` | 節の書きかけの印。行に単独で置く |

上の記法以外の文字は、そのまま本文になる。

### 画像

本文に画像を一枚置くには、行に単独で次のように書く。

```
![キャプション](画像の道)
```

- 道は原稿からの相対の道（`zu.png`・`images/zu.png`）。URL や絶対の道（`/a.png`・`C:\a.png`）は使えない
- 埋め込めるのは PNG・JPEG・GIF・WebP・SVG で、1 枚 2 MiB まで
- キャプションは空でも読めるが、検査が `IMAGE-CAPTION` で警告する
- 画像は段落・箇条書きと同じ「まとまり」として並ぶ。行の途中に書くと読み取りのエラーになる
- 同梱の画像（国旗 60 件）は `![日の丸](bundle:flags/jp.svg)` と目録のキーで指せる。HTML は data: の URI、ウィキテキストは本家のファイル名（`Flag of Japan.svg`）になる。キーと許諾は `plugins/wiki-style-article/skills/wiki/assets/images/manifest.toml` に並ぶ
- HTML には画像そのものを data: の URI として埋め込み、ウィキテキストにはファイルの名前だけを書く（次節以降の各文書）
- Infobox の画像の項目も同じように書く（`[infobox]` の項目に `![キャプション](画像の道)`）。どの項目が画像かは型の定義が決める（設定欄の `[infobox]` を参照）。`_template` を書いたときは定義を使わないので、本家が画像を受け取る引数にこの記法を書く（設定欄の「任意のテンプレート」）。ファイル名だけを渡す引数は `_image_fields` に並べる
- 地図や議席図の図は、`figure` のサブコマンドで SVG を作り、その道をこの書き方で置く（[コマンドの入口](cli.md#地図と議席図figure)）。選挙の州別の結果の地図は、同梱の `us-states` の形の地域コード（`TX`・`DC` など）で塗れる

読み取りでは、印が指すキーが設定欄にあるかは見ない（後の検査で扱う）。ただし、閉じていない `[[`・`[^`・`'''`・`[!`、空のキー、使えない文字のキーなど、記法として壊れているものは行番号つきのエラーにする。

### 座標・ナビゲーションの箱・スタブ

導入部の先頭に出す座標、記事の末尾に置く表、書きかけの印は、本文ではなく設定欄で書く。

```toml
stub = "Japan-geo-stub"

[coord]
lat = 35.681236
lon = 139.767125
type = "city"

[[navbox]]
title = "日本の都市"
name = "Cities"
items = ["東京", "大阪", "名古屋"]
```

- `[coord]` は記事の座標。`lat`・`lon` は度の十進で書き（南緯・西経は負）、`lat` は -90 から 90、`lon` は -180 から 180 の間。`type` は本家の `type:` に渡す値（`city`・`mountain`・`airport` など）で、書かなければ付けない。`display` は `title`（既定）・`inline`・`dms`・`inline,title` のどれか
- 座標は HTML では導入部の先頭に「座標: 北緯35度40分52秒 東経139度46分02秒」と出し、その文言を本家の GeoHack へのリンクにする。ウィキテキストはページの先頭に `Coord` テンプレートの行（緯度・経度・`type:`・`display=title` の順）を置く
- `[[navbox]]` は記事の末尾（外部リンクの後、カテゴリの前）に置く表。`title` が必須で、`name`（本家のテンプレート名）・`state`（`collapsed` など）・`items`（並べる項目の配列）は任意。複数書ける
- `stub` は記事の末尾（ナビゲーションの箱の後、カテゴリの前）に置く書きかけの印。値は本家のテンプレート名（`Japan-geo-stub`）。`{` `}` `|` `[` `]` と改行は書けない
- 表の配列 `[[navbox]]` より後ろに素のキーを書くと、そのキーは navbox の表に入る。`stub`・`categories`・`[coord]` は `[[navbox]]` より前に書く
- 文中の印は三つ。`[!仮リンク|言語タグ|本家の記事名]`（表示は省略でき、省くと本家の記事名を表示する）は、HTML では赤字の内部リンクに「（英語）」の注記を添え、ウィキテキストでは本家の仮リンクのテンプレート（引数は 表示・言語タグ・本家の記事名 の順）にする。`[!言語|言語タグ]` は言語の名前（HTML は文字、ウィキテキストは ISO 639 言語名のテンプレート）。`[!節スタブ]` は行に単独で置き、HTML は「この節は書きかけです。」の枠、ウィキテキストは節スタブのテンプレートにする

座標・navbox・stub の書き方の誤りは `SettingsError`、印の誤り（`|` の数、言語タグの形、行に単独でない `[!節スタブ]` など）は `MarkupError` になる。どちらも行番号つき。

### 印

確かめられなかった事実や噂を載せるときに、本家の「要出典」などに当たる印を文に付ける。

| 書き方 | 種類 | 使う所 |
| --- | --- | --- |
| `[!要出典]` | 点の印 | 出典の無い文の直後 |
| `[!信頼性要検証]` | 点の印 | 弱い出典の印の直後（`[^wiki][!信頼性要検証]`） |
| `[!要出典範囲\|範囲の文]` | 範囲の印 | 出典の無い範囲を包む |
| `[!独自研究範囲\|範囲の文]` | 範囲の印 | 出典で確かめられていない見方や推測の範囲を包む |

- 範囲の文には、文字・内部リンク `[[…]]`・出典の印 `[^キー]`・注釈の印 `[^n:キー]` を書ける。太字と、印の入れ子は書けない
- 範囲の終わりは `[` と `]` の入れ子を数えて決める。`[!独自研究範囲|[[記事|表示]]の話]` の `[[…]]` の中の `]` や `|` で範囲は閉じない。範囲の文の中の `=` や `|` は、そのまま文字になる
- 太字の中にも点の印を置ける（`'''名物[!要出典]'''`）。範囲の印は置けない
- 注釈の本文（`[notes.<キー>]` の `text`）にも印を書ける

次のものは行番号つきの `MarkupError` になる。知らない印の名前（`[!要確認]`）、閉じていない `[!`、点の印に `|` がある（`[!要出典|…]`）、範囲の印に `|` が無い（`[!要出典範囲]`）、範囲の文が空（空白だけも）。

### 外国語の原文

外国語の引用は、日本語訳の後ろに `（原文：[!原文|en|Their work disregarded the blur.]）` の形で原文を添える。

- 言語タグは BCP 47 の形（`en`・`en-US`・`zh-Hans`・`ko`）。形が違う、文が空、閉じていないとき、原文の文に `[^`・`[!`・`[[` があるときは行番号つきの `MarkupError`
- 文の中の `|` と、対になった `[` `]` はそのまま文字になる。前後の空白は取る
- 太字・範囲の印の中には書けない。噂の範囲 `[!噂|…]` の中には書ける（入れ子は噂の中だけ）。脚注の印は原文の外に置く
- HTML は `<span lang="タグ">文</span>`、ウィキテキストは `{{lang|タグ|文}}`（文に `=` があれば `{{lang|タグ|2=文}}`）、`plain` の書き方は文字だけ
- 検査は、原文の範囲を和文用の規則（`checks/` のすべての文字の規則）から外す。範囲の外は今までどおり
- ブロック引用 `{{Quotation}}` は未対応

### 噂

噂や利用者の見方を、通常の記事と噂込みの記事の二つの版に分けて書くための記法（スキル `wiki-both`）。一つの原稿から、噂を除いた通常の版と、噂を含めた噂込みの版を作る。

| 書き方 | 意味 |
| --- | --- |
| `[!噂\|範囲の文]` | 文の中の噂の範囲。通常の版では範囲ごと取り除き（前後の文字は残す）、噂込みの版では範囲の文だけを残す |
| `## 騒動 [!噂]` | 節ごと噂。見出しの末尾に ` [!噂]` を付けると、その節と子の節のすべてが噂になる。通常の版では節ごと取り除く |

- 範囲の文には、文字・内部リンク・太字・出典の印 `[^キー]`・注釈の印 `[^n:キー]`・点の印 `[!要出典]` `[!信頼性要検証]`・範囲の印 `[!要出典範囲|…]` `[!独自研究範囲|…]` を書ける。噂の範囲の入れ子は書けない
- 範囲の終わりは、範囲の印と同じく `[` と `]` の入れ子を数えて決める
- 段落や箇条の項目が `[!噂|…]` 一つだけでできているもの（前後に空白以外の文字が無い）は「噂だけのまとまり」で、通常の版では段落・項目ごと取り除く。噂の範囲を取り除いて空白しか残らない段落・項目も同じ
- 噂の範囲は太字や範囲の印の中には書けない。逆に、太字や範囲の印を噂の範囲の中に入れる
- 注釈の本文にも噂の範囲を書ける。通常の版では取り除く
- 節の本文がすべて噂なら、文ごとに `[!噂|…]` で包まずに節ごと噂にする（通常の版に空の節が残らないように）

次のものは行番号つきの `MarkupError` になる。閉じていない `[!噂|`、空の範囲（空白だけも）、入れ子の `[!噂|`、`|` の無い `[!噂]`（見出しの末尾のほか）、太字や範囲の印の中の噂の範囲、見出しの末尾以外の `[!噂]`（`## [!噂] 騒動` など）。

二つの版への分け方は `wikiskill.variants` にまとめてある。

| 関数 | 結果 |
| --- | --- |
| `has_rumor(article)` | 噂の範囲か噂の節が一つでもあるか |
| `normal_view(article)` | 通常の版。噂の範囲・噂だけのまとまり・噂の節（子を含む）を取り除く。取り除いた結果どこからも使われなくなった出典・注釈を設定欄から外す（元の原稿でも使われていないものは、検査の `REF-UNUSED` で知らせるために残す）。`notices` から `観点` を外す |
| `rumor_view(article)` | 噂込みの版。噂の範囲を中身にほどき、噂の節の印を外す。噂が一つでもあれば `notices` に `観点` を足す（重ねない） |

どちらの版も噂の部品を持たないふつうの記事なので、検査（[checks.md](checks.md)）と書き出し（[html.md](html.md)・[wikitext.md](wikitext.md)）にそのまま渡せる。噂のある原稿を `write_html`・`write_wikitext` に分けずに渡すと例外になる。

### 警告の枠

記事に印があると、HTML とウィキテキストの冒頭（Infobox より前）に、記事全体の問題を知らせる警告の枠を貼る。枠は印の種類から決まり、設定欄の `notices` で足せる。印から決まる枠を付けるかは、設定欄の `notice_rule` で決める（スキルは生成の前に利用者に聞く）。

| 枠 | 決まり方 |
| --- | --- |
| `出典の明記` | 本文か注釈の `要出典`・`要出典範囲`・`信頼性要検証` の印が、`notice_rule` の線を越える |
| `独自研究` | 本文か注釈の `独自研究範囲` の印が、`notice_rule` の線を越える |
| `観点` | `notices = ["観点"]` と書いたときだけ（噂や利用者の見方を載せた記事に使う） |

`notice_rule` の線は次のとおり。数えるのは本文と注釈の脚注の印（`[^キー]`）と、その種類の印。

- `多いときだけ`（既定）: その種類の印の数が、脚注の印と印を合わせた数の 2 割以上（脚注 20・`要出典` 2 なら付けず、5 なら付ける）。本物でも、要出典が数か所あるだけの記事に枠までは貼らないため
- `付けない`: 付けない。本文の印は残る
- `付ける`: 印が一つでもあれば付ける

`notices` に書いた枠は、`notice_rule` によらず印から決まる枠に足し、重ねない。噂込みの版の `観点` もこれに当たる。並びは 出典の明記・独自研究・観点 の順。決め方は `wikiskill.notices.article_notices` にまとめてあり、書き出しはどちらもこれを使う。

## 読み取り結果

```text
Article
├─ settings: Settings        設定欄の中身（infobox・references・notes は書いた順）
├─ lead: tuple[Block, ...]   導入部（Paragraph / BulletList の並び）
└─ sections: tuple[Section, ...]   ## の節。各 Section が blocks と一段下の children を持つ
```

段落と箇条書きの中身は、文中の部品（`Text`・`Bold`・`RefMark`・`NoteMark`・`InternalLink`・`FixMark`・`FixRange`・`RumorRange`）の並び。隣り合う文字は一つの `Text` にまとめる。点の印は `FixMark(kind)`、範囲の印は `FixRange(kind, children)` で、`children` は範囲の文の部品（`Text`・`InternalLink`・`RefMark`・`NoteMark`）。`Bold` の子には `FixMark` も入る。噂の範囲は `RumorRange(children)` で、`children` には `Text`・`InternalLink`・`RefMark`・`NoteMark`・`Bold`・`FixMark`・`FixRange` が入る。節ごと噂は `Section.rumor`（既定 `False`）で、噂の節の子の節は `rumor` が `False` のまま（親が噂なら子も噂として扱う）。出典の `weak` は `Reference.weak`（既定 `False`）、設定欄の `notices` は `Settings.notices`（既定 `()`）に入る。

`Paragraph`・`BulletList`（と項目ごとの `item_lines`）・`Section`・`InfoboxField`・`Reference`・`Note`・`ExternalLink` は、原稿ファイル全体での行番号を `line` に持つ（段落と箇条書きの項目は先頭の行。出典は `[refs.キー]` の見出しの行で、項目ごとの行は `Reference.line_of("url")` で引く）。検査の結果に行を載せるためのもので、等しさの比較には使わない。検査は [checks.md](checks.md)。

## エラー

読み取りで見つけた誤りは、原稿ファイル全体での行番号（1 始まり。冒頭の `+++` が 1 行目）つきの例外になる。例外はすべて `wikiskill.SourceError` の仲間で、`.line` と `.message` を持つ。

| 例外 | 原因 |
| --- | --- |
| `FrontMatterError` | 設定欄を囲む `+++` の行がない・閉じていない |
| `SettingsError` | TOML として読めない、必須の項目がない、型や値が合わない、未知の項目がある |
| `MarkupError` | 本文や文中の記法が壊れている（使えない見出し、飛んだ階層、入れ子の箇条書き、閉じていない `[[`、知らない印の名前など） |

設定欄の誤りの行番号は、その項目の行を書かれた文字列から探して求める。必須の項目がないときはその表の見出しの行（最上位なら冒頭の `+++`）を指す。ドット付きのキーや一行の表で書かれた項目は探せないため、冒頭の `+++` の行を指すことがある。
